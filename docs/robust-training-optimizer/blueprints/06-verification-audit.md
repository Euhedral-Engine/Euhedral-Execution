# Phase 6 Blueprint: Executable End-to-End Verification and Audit

Status: Prompt 6B completed on 2026-07-29

This blueprint defines the Phase 6 executable audit. It does not change any statistical,
scheduling, checkpoint, packaging, import, or CLI contract settled by Phases 1-5. Prompt 6B must
add the fixtures and test harness below, execute the commands in order, and repair only defects
whose resolution is already fixed by an approved blueprint.

## Scope

Phase 6 must prove the integrated upgraded path, not merely rerun isolated unit tests. It must:

1. import exact current-workspace vectors while rejecting legacy measurements and artifacts;
2. decode one strict typed configuration without ambient properties;
3. bootstrap four exact scenarios across two environments;
4. calibrate later runs against frozen anchors at known global speed factors;
5. produce a known robust ranking in which the winner is second-best in every scenario;
6. interrupt one normal iteration after its first scenario bundle, package that recoverable
   checkpoint, resume it without changing the schedule, and finish the run;
7. compare the resumed run to an uninterrupted control using the same seeds and immutable inputs;
8. validate every lifecycle package, final inventory, checksums, provenance, reports, collision,
   tamper, atomicity, and deterministic-byte requirement already settled by Phase 4;
9. close the parser, filesystem, configuration, stop, and command test gaps recorded by the Phase
   5 conformance audit;
10. run the focused and full deterministic suites; and
11. classify failures as code defects, environment limitations, or deliberately retained Phase 7
    cleanup seams using the criteria below.

The audit is successful only when its required deterministic tier passes. A passing Maven command
without the assertions below is not equivalent evidence.

### Explicit non-goals

- Do not change policy or scenario identity, anchor selection, calibration, aggregation,
  percentile quality, the robust comparator, or uncertainty mathematics.
- Do not change model features, targets, split rules, acceptance gates, or artifact schema.
- Do not change budget allocation, candidate comparison, carry rules, rotation, run identity,
  checkpoint transitions, or evidence schema.
- Do not change package layout, manifest schema, lifecycle mapping, provenance rules, atomic-only
  publication, or collision behavior.
- Do not broaden the temporary importer, infer legacy measurement identity, or import a legacy
  model/checkpoint.
- Do not use the real `euhedral-training/input`, `euhedral-training/output`, or `data` trees.
- Do not run a live lattice, train a DJL model, or make throughput/performance claims in the
  deterministic end-to-end test.
- Do not bless output by copying a generated workspace package into source resources. Golden
  expectations must be independently declared and compared to generated bytes.
- Do not delete the marked pooled-v0 or temporary-importer seams; Phase 7 owns deletion.
- Do not turn an environment limitation into a source/build workaround.

### Known ranking oracle

Immediately after native bootstrap and before normal scheduling, each exact scenario contains ten
valid policies. Its ordered throughput/quality oracle is:

```text
three nonmatching specialists: throughput 5, tied quality 1/9
A0: 10 -> 3/9
A1: 20 -> 4/9
A2: 30 -> 5/9
A3: 40 -> 6/9
A4: 50 -> 7/9
R:  90 -> 8/9
matching specialist: 100 -> 1
```

Therefore the exact eligible robust order after bootstrap is:

```text
R, A4, A3, A2, A1, A0, then S0..S3 by unsigned PolicyId
```

`R` has:

```text
worst_quality                = 8/9
quality_p25                  = 8/9
geometric_mean_quality       = 8/9
cross_scenario_quality_mad   = 0
```

Each specialist has qualities `{1, 1/9, 1/9, 1/9}`, minimum and type-7 P25 `1/9`, and cannot
outrank `R`.

After normal iterations, generated policies may enlarge a scenario's percentile population.
The final oracle therefore asserts exact relative ordering rather than reusing the bootstrap
numeric denominator:

- `R` is published rank 1;
- `R` is second by calibrated throughput in every required scenario;
- all four specialist policies remain eligible but rank below `R`;
- every scenario row for `R` has the independently calculated midrank quality among that
  scenario's valid rows, and its minimum, type-7 P25, geometric mean, and type-7 MAD are
  independently recalculated from those four persisted qualities;
- the intentionally failed generated policy is ineligible with the exact rejected/missing
  scenarios; and
- no incomplete policy has a published rank or leader-revalidation role.

The test must calculate the expected final midranks independently from sorted calibrated
throughput rows, using the settled tie formula, and compare them to persisted `quality` values.
It must not call `ScenarioQualityRanker` to construct the expected values.

## Determinism, memory semantics, memory pollution, and precision

### Determinism

- All collections with serialized or asserted order are explicit sorted collections or immutable
  ordered lists.
- Seeds, timestamps, run boundaries, stop points, source creation order, and output roots are fixed
  as above.
- Expected values do not depend on a thread schedule, filesystem order, locale, default charset,
  hostname, wall clock, or random UUID.
- Compare complete artifact bytes in addition to decoded records.

### Memory semantics

The end-to-end audit is single-threaded above the production benchmark boundary. Fake services,
fault probes, row buffers, and invocation counters are thread-confined. Published production
records remain immutable and publication remains through the existing atomic filesystem
boundaries.

No Phase 6 test seam may alter the release/acquire semantics of benchmark counters, checkpoint
ownership, workspace locking, or atomic rename. The existing core `BenchmarkFrameTest` and Phase 3
fake benchmark tests remain the evidence for hot-path ordering. Any production memory-access
change is outside Phase 6 and requires a new blueprint.

### Memory pollution

- Do not load DJL in the deterministic experiment or package validation.
- Exercise files larger than 128 KiB for importer, artifact hashing, and raw observation traversal.
- Do not use `Files.readAllBytes` or `readAllLines` on those large fixtures.
- Retain only the current file/run rows needed by the fixture; do not retain a corpus-sized mirror
  merely to calculate expected checksums.
- Run all benchmark simulation outside core hot loops. No test instrumentation enters
  `ControlPlaneFragment`, frame execution, queue operations, or native affinity code.

### Mathematical precision

- Preserve all 28 policy lanes by raw IEEE-754 bits.
- Use integer frames and elapsed nanoseconds for native observation throughput.
- Compare exact calibration values using the specified `StrictMath` evaluation order and raw bits.
- Independently calculate type-7/midrank expectations from exact sorted doubles.
- Do not round, format-parse, use a tolerance as comparator authority, pool repetitions across
  runs, or use a candidate cohort to define scale.
- SHA-256 is over exact bytes. Text is UTF-8, LF-terminated, and locale-independent.

## Defect versus environment classification

Classify as a **code defect**:

- any required deterministic test failure, nondeterministic byte, incorrect ranking/calibration,
  changed schedule on resume, duplicate benchmark, wrong lifecycle inventory, checksum/report
  mismatch, unsafe cleanup, silent non-atomic fallback, parser/config/CLI mismatch, prohibited
  dependency, or stale new-path pooled/P99 assumption;
- inability to construct or validate an earlier-blueprint-required fixture because production lacks
  an already-required validation or package-private test boundary;
- a build failure caused by source, test, schema, or deterministic fixture code under the pinned
  supported toolchain.

Classify as an **environment limitation** only with exact evidence:

- missing/incompatible PyTorch native runtime for the opt-in DJL smoke;
- unavailable Docker daemon for Testcontainers;
- missing Zig, macOS SDK, cross-target JNI headers, or native toolchain for hardware verification;
- missing JDK 25 for Reactor/benchmark modules while Java 21 trainer commands pass;
- unavailable CPU affinity/topology for a live native-lattice smoke;
- filesystem provider genuinely lacking atomic rename, provided the required failure/cleanup
  assertion passes and production does not fall back;
- unsupported FIFO creation, after symlink/regular-file safety assertions pass;
- sandbox denial or unavailable network dependency after the prescribed compatible installed
  toolchain/cache alternatives are exhausted.

An environment limitation never permits skipping the deterministic fake end-to-end, merge,
checkpoint, package, importer, configuration, or command tests. Record the command, exit status,

   be accepted as idempotent. Collision validation now resolves the requested source and compares
   checkpoint hash/stage/status, calibration, winners, and omissions before returning the
   existing target.
5. The exact Phase 5 command grammar did not reject a flag token in an argument-value position.
   `Runner` now rejects those malformed forms before invoking any service.

the Phase 1 valid-row population rule: the intentional rejected row changes one scenario's
midrank denominator. The oracle above now requires independent scenario midranks and independent

fixture assertion, not a new statistical decision.
